Homelab Agent-Cluster — Project Plan

Owner: Borna · Last updated: July 31, 2026 · Linux comfort: 3/5

A 3-node Kubernetes homelab that hosts your own apps (GitOps) and runs AI coding agents in pre-warmed, disposable environments, all viewable through herdr.

On this page: Architecture · Goals · Definition of done · Decisions · Principles · Build plan · Repo · Day-2 ops · Risks · Glossary

Architecture

1 · Whole project — the full stack

Read bottom-up: hardware → OS → Kubernetes → platform services → workloads → access. Everything on the left rail is code in one git repo — cloud-init and Ansible build the OS/Kubernetes layers, Argo CD manages everything inside the cluster.

2 · How agents run — herdr + Agent Sandbox + warm pools

You issue a SandboxClaim, get a pre-booted pod instantly, and herdr kubectl execs into it to run Claude Code or Codex — watching each agent go working → done. When finished, the pod is recycled and the pool refills. The warmups are the SandboxWarmPool keeping pods hot so there's no cold start.

Goals

  • Learn Kubernetes properly — the real, upstream way (kubeadm), not a black box.
  • Run AI coding agents (Claude Code, Codex; PI later) in isolated, disposable pods, pre-warmed and preloaded with a project (example: a modern Ruby on Rails app).
  • Host my own apps on the same cluster, managed by GitOps.
  • Everything as code — nodes and cluster reproducible from a git repo; never configure a machine by hand 3×.
  • Reachable & observable — access from anywhere over Tailscale, apps by hostname over HTTPS, Grafana dashboards for health.

Definition of done

  • Three identical Ubuntu nodes stood up from one autoinstall + Ansible run.
  • A working kubeadm cluster with CNI, storage, ingress, and a bare-metal load balancer.
  • Argo CD syncing all cluster state from a git repo.
  • Apps reachable by hostname over HTTPS (internal DNS + cert-manager).
  • Grafana showing live node/pod metrics; a test alert fires.
  • A rails-dev sandbox image; Agent Sandbox warm pool hands over a ready pod in ~ms.
  • herdr driving 2 agents in 2 warm pods at once.
  • Cluster reachable from outside the house over Tailscale.
  • At least one hosted app deployed via GitOps in its own namespace.
  • An etcd snapshot taken and a restore rehearsed once.

Guiding principles

  • Everything as code, in one git repo. If it's not in git, it doesn't exist.
  • Learn first, automate second. Do a step by hand once, then capture it in Ansible/Argo.
  • Climb the ladder. Single control-plane before HA; requests-based scheduling before load-aware; metrics before logs.
  • One cluster, logical isolation. Namespaces, taints, quotas, NetworkPolicies — not more hardware.
  • Security baseline is non-negotiable. Named sudo user, Ed25519 keys, locked-down SSH, default-deny firewall, encrypted secrets, drained reboots.
  • Mind the SSD. 256 GB is the tightest resource — lean images, capped retention, /var on its own LVM volume.
  • Contain the blast radius. --dangerously-skip-permissions only inside sandbox pods; spend caps on agent API keys.

Build plan

Do phases in order; each ends in a working state. Full detail lives in homelab-roadmap.md.

Phase 0 — Prep

Everything staged.
  • Plan node names + static IPs
  • BIOS: USB boot, VT-x, AC-recovery on
  • Collect keys/accounts
  • Create git repo + cloud-init autoinstall
Done: autoinstall USB + empty repo ready

Phase 1 — Base OS

Three clean nodes.
  • Unattended Ubuntu install on all three
  • Key-only SSH from laptop
Done: ssh to all nodes, no passwords

Phase 1.5 — Ansible

Never configure a node by hand.
  • Inventory + ansible all -m ping
  • Baseline + K8s prereqs playbooks
  • ansible-vault for secrets
Done: one playbook → identical, hardened nodes

Phase 2 — kubeadm

A real cluster.
  • containerd, swap off, sysctls
  • kubeadm init (1 CP) + join 2 workers
  • Cilium CNI; k9s on laptop
  • Later: 3 CP + kube-vip (HA)
Done: all nodes Ready

Phase 2.5 — Batteries

What kubeadm omits.
  • MetalLB, Traefik
  • local-path storage
Done: app+PVC reachable via ingress

Phase 2.75 — Hostname access

Reach apps by name over HTTPS.
  • Local DNS wildcard → ingress IP
  • cert-manager (TLS); ExternalDNS optional
  • Later: Tailscale Split DNS
Done: https://app.home.arpa works

Phase 3 — Hygiene

Backups, GitOps, secrets.
  • etcd snapshot + rehearse restore
  • Argo CD + app-of-apps repo
  • SOPS/Sealed Secrets; store API keys
  • Cert-renewal reminder (~1 yr)
Done: snapshot + Argo + encrypted secrets

Phase 3.5 — Monitoring

See the cluster.
  • kube-prometheus-stack (retention capped)
  • metrics-server; kubectl top
Done: Grafana live; test alert fires

Phase 4 — Rails image

"My project, ready."
  • Dockerfile: Ruby+Node+git+agents
  • Push to registry (TLS+auth)
  • Test as a one-off pod
Done: Rails + agents run in the image

Phase 5 — Agent Sandbox

Pre-warmed envs.
  • Install controller + CRDs
  • SandboxTemplate rails-dev
  • SandboxWarmPool (N=2)
  • Test claim → hot pod → recycle
Done: claim yields a warm pod instantly

Phase 6 — herdr

The cockpit.
  • Install herdr; one pane per agent
  • exec into sandbox pods; run claude/codex
Done: 2 agents in 2 pods, one view

Phase 7 — Tailscale

Reach it anywhere.
  • Tailscale + subnet router (home node)
  • Keep pod traffic on native LAN
Done: drive cluster from outside home

Ongoing / later

After the base is solid.
  • Hosted apps via GitOps
  • Descheduler → Trimaran (load-aware)
  • Loki (logs); Longhorn (if disks added)
  • HA control plane; vCluster
Optional futures

Day-2 operating guidelines

  • Node reboots/upgrades: always kubectl drain → reboot → kubectl uncordon. Never let all nodes auto-reboot together.
  • Add a node: one line in Ansible inventory → re-run site.yml → kubeadm join.
  • Backups: scheduled etcd snapshots; back up PVs that matter; rehearse a restore.
  • Certs: renew kubeadm control-plane certs before the ~1-year expiry.
  • Secrets: rotate API keys; keep spend caps on them.
  • Capacity: watch Grafana for pressure and df -h for SSD; keep images/retention lean.
  • Change flow: edit git → Argo CD syncs. Avoid manual kubectl apply for anything Argo manages.

Secrets leak / token burnSOPS/Sealed Secrets; spend caps; skip-permissions only inside pods

Learning overloadFollow the ladder; one phase at a time; each rung is usable

Beginner glossary

NodeOne physical machine in the cluster.
PodSmallest deployable unit; one or more containers.
NamespaceLogical partition for grouping/limiting workloads.
DeploymentKeeps N identical pods running.
Service / Ingress / LoadBalancerHow traffic reaches pods (MetalLB gives real LAN IPs on bare metal).
CNIThe pod network plugin (Cilium).
etcdThe cluster's database (quorum needs an odd number of control-plane nodes).
requests / limitsWhat a pod reserves vs its hard ceiling (the scheduler places by requests).
taint / tolerationKeep pods off a node unless they explicitly tolerate it.
GitOps / Argo CDCluster state lives in git; the controller makes reality match it.
SandboxTemplate / WarmPool / ClaimAgent Sandbox: env definition / pool of pre-booted pods / request for one.
